# 暖湾小镇：OhMyGame 协作与验收流程

## 生产闭环

1. 在 OhMyGame Canvas 建立世界总文档，并连接世界区域、角色、房屋、生物、植物和天空参考节点。
2. 先生成概念图、色彩脚本和角色转面图，确认轮廓、比例、材质和镜头，不把概念图直接当运行时资源。
3. 为一个 Hero 资产生成 GLB，保存到 staging；使用 Blender 5.2 清理拓扑、材质、骨骼、动画、pivot、LOD 和碰撞代理。
4. 将通过检查的 GLB 放入 `public/assets/`，更新 `src/game/world-assets.ts` 或对应资产注册表，通过稳定 key 加载。
5. 让 OhMyGame 或 Codex 修改 Three.js 接入代码，但保留当前 Vite、Three.js、Rapier 和存档协议。
6. 运行逻辑检查、构建、HTTP smoke，再做浏览器视觉和交互检查；发现问题回到资产或运行时对应环节。
7. 本地验收通过后再使用 OhMyGame 静态发布；发布只证明构建可访问，不替代视觉验收。

## 测试层级

- **资产检查**：GLB 可加载；尺度、朝向、pivot、材质、贴图、节点、动画和碰撞代理正确。
- **逻辑检查**：`pnpm typecheck`、`pnpm test`。
- **构建检查**：`pnpm build`，确认静态输出和资源路径。
- **HTTP 检查**：`pnpm smoke`，确认游戏入口、户型编辑器、网站和静态资源响应。
- **浏览器检查**：确认初始画面非空、角色比例、路线、房屋内外切换、建造保存、控制输入和移动端布局；捕获 overview、route、hero close-up、interior、night-sky 五类截图。
- **性能检查**：记录加载失败、控制台错误、主要 GLB 大小、渲染帧率和移动端表现；不能用对象数量代替视觉完成度。

## 首个切片的完成定义

角色、房屋、河谷、生物和夜空至少各有一项可运行 Hero 资产；玩家能从舱外沿真实路面走到河谷并返回；房屋结构编辑保存后重开仍可恢复；没有未解释的加载错误；四类本地检查和浏览器视觉检查分别有记录。

## 不能夸大的边界

OhMyGame 可以编排设计、生成、代码和 playtest，但不能保证 AI 生成模型的拓扑、贴图、骨骼或审美质量。Meshy 等 3D 服务需要自己的 provider/API key，视频主要用于设计参考和展示。自动 playtest 也不能替代人工看图和真实设备验收。
